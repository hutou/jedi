Jedi 1.0 — Aides des commandes

===== database dump =====

Description :
  Génère un jeu de commandes jedi pour reconstituer une base de données

Usage: 
  jedi database dump [>filename] [options]
  (la sortie standard est utilisée, généralement redirigée vers un fichier)

Options :
  -h, --help                       Affiche cette page d'aide

Exemple: 
  jedi database dump >jedidump.txt

===== database load =====

Description :
  Alimente une base de données vide à partir d'un fichier

Usage: 
  jedi database load <filename>
  (La base de données doit être vide)

Argument requis :
  <filename>                       Nom du fichier issu de la sous-commande 'database dump' redirigée

Options :
  -h, --help                       Affiche cette page d'aide

Exemple :
  jedi database load jedidump.txt

===== database schema =====

Affiche le schéma de la base de données, ainsi que son résumé sha256

Usage: 
  jedi database schema
  (la sortie standard est utilisée)

Options :
  -h, --help                       Affiche cette page d'aide

Exemple :
  jedi database schema

===== main =====

jedi, version 1.0.0

L'application jedi est utilisable en mode 'ligne de commande' uniquement
et répond à la syntaxe suivante : 

jedi [options globales] commande sous-commande arguments [options]

La saisie d'une commande seule permet d'afficher la liste des
sous-commandes disponibles pour cette commande.

- Arguments et options ne s'appliquent qu'à la sous-commande qui
  les précède.
  A ce niveau sont définis :
  . le caractère obligatoire ou non des arguments
  . la disponibilité d'options
- Si aucun argument n'est requis, la sous-commande est immédiatement
  exécutée.
- Toutes les sous-commandes disposent d'une page d'aide avec l'option -h ou --help.

Un double tiret "--" doit être utilisé pour séparer les options et
les arguments positionnels (obligatoire si ceux-ci commencent par
un simple tiret, comme les nombres négatifs). Attention donc au placement
des options dans ce cas; elles doivent toujours précéder le double-tiret.

Lorsqu'une option ou un argument positionnel attend une liste,
les éléments de cette liste doivent être séparés par une virgule,
sans espace intermédiaire (sauf si entourés de double quotes).

Commandes :
  security                         Gère les titres cotés (titres, ETF, fonds…)
  quote                            Gère les cotations
  trade                            Gère les trades (create, update, ...)
  scale                            Gère les barèmes (Type I et type II)
  settings                         Gère les paramétrages (barème, split, etc.)
  operation                        Gère les opérations
  note                             Gère les notes
  database                         Gère la base de données
  market                           Gère les bases de cotations de marché
  tools                            La boîte à outils de Jedi

  version                          Affiche des informations détaillées sur la version
  config                           Affiche les données de configuration
                                   (Utiliser l'option --paths pour n'afficher que les fichiers utilisés)
                                   
Notes:
  Les commandes et sous-commandes peuvent être abrégées jusqu'au préfixe non ambigu le plus court.

Options globales :
  -b, --border=PRESET              Selectionne le style d'encadrement, parmi les valeurs suivantes :
                                     - ascii         - modern         - markdown   - empty 
                                     - reducedascii  - reducedmodern  - fancy      - blank

===== market group =====

Description :
  Ajoute un titre à un groupe existant ou l'en retire.

Usage :
  jedi market group <source> <groupe> <ISIN> (--add | --remove) [options]

Arguments requis :
  <source>                         Source de la base
  <groupe>                         Code du groupe existant
  <ISIN>                           Code ISIN du titre

Options :
      --universe=NAME              Univers général utilisé dans le nom de la base (défaut : france)
      --add                        Ajoute le titre au groupe
      --remove                     Retire le titre du groupe
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi market group abcbourse PEA FR0000031122 --add
  jedi market group abcbourse PEA FR0000031122 --remove

===== market import =====

Description :
  Ajoute un ensemble de titres et de cotations dans une base existante.
  Les ISIN sans libellé sont ignorés et recensés dans le rapport.

Usage :
  jedi market import <source> <dataset> <quotes> <labels> [options]

Arguments requis :
  <source>                         Source de la base
  <dataset>                        Code libre du dataset, par exemple Euronext_A
  <quotes>                         Fichier de cotations
  <labels>                         Fichier de libellés ISIN;Name;Ticker

Options :
      --universe=NAME              Univers général utilisé dans le nom de la base (défaut : france)
      --date-order=ORDER           Ordre de date : auto, ymd, dmy ou mdy (défaut : auto)
      --year-pivot=NN              Pivot des années sur deux chiffres, de 0 à 99 (défaut : 70)
      --from=DATE                  Première date de cotation conservée, au format AAAA-MM-JJ
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi market import abcbourse Euronext_A Euronext_A.txt labels.txt
  jedi market import abcbourse Euronext_A Euronext_A.txt labels.txt --from=2020-01-01

===== market list =====

Description :
  Liste les titres présents dans la base de marché. L'option --dataset
  permet de limiter la liste à un dataset. Un filtre regex facultatif peut
  porter sur l'ensemble des champs ou sur un champ nommé.

Usage :
  jedi market list <source> [regex] [options]

Arguments requis :
  <source>                         Source de la base

Filtres :
  [regex]                          Filtre regex, insensible à la casse, appliqué à 
                                   la concaténation des champs filtrables. 
                                   && = ET, || = OU, avec priorité de && sur ||.
                                   Exemples : abc, abc && xyz, abc || xyz, a && b || c && d.
                                   Chaque terme est une regex indépendante. L’ordre des champs
                                   n’a pas d’importance. Parenthèses non prises en charge.

                                   Les champs filtrables sont : isin, ticker, name, group, dataset.
Options :
      --universe=NAME              Univers général utilisé dans le nom de la base (défaut : france)
      --dataset=CODE               Limite le rapport au dataset indiqué
      --last-quote                 Ajoute la date et la clôture de la dernière cotation
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi market list abcbourse
  jedi market list abcbourse air
  jedi market list abcbourse 'group=PEA && name=air'
  jedi market list abcbourse --dataset=Euronext_Growth
  jedi market list abcbourse 'ticker=^AL' --dataset=Euronext_A
  jedi market list abcbourse --last-quote

===== market quote =====

Description :
  Affiche l’historique OHLCV complet d’un titre de la base de marché.
  La sélection par date est appliquée avant la sélection d’enregistrements.

Usage :
  jedi market quote <source> <ISIN> [options]

Arguments requis :
  <source>   Source de la base
  <ISIN>     Code ISIN du titre

Options :
      --universe=NAME              Univers général utilisé dans le nom de la base (défaut : france)
  -s, --select=RECORDS             Sélectionne uniquement les enregistrements définis 
                                   dans RECORDS, une liste d'éléments séparés par des 
                                   virgules, avec la syntaxe suivante :
                                   - la lettre F ou L (insensible à la casse), suivie 
                                     d'un entier, pour désigner respectivement les premiers 
                                     ou les derniers enregistrements à sélectionner
                                   - un nombre entier positif (ou négatif pour l'indexation 
                                     en fin de tableau)
                                   - une plage composée de deux entiers, positifs ou négatifs, 
                                     séparés par deux points
                                   Exemple : "f10,-12:-1" pour sélectionner les 10 premiers 
                                             enregistrements et les 12 derniers.
      --date=OP:DATE               Sélectionne une période avec OP:AAAA-MM-JJ (ge, gt, le ou lt)
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi market quote abcbourse FR0000120073
  jedi market quote abcbourse FR0000120073 --date=ge:2026-01-01
  jedi market quote abcbourse FR0000120073 --select=20
  jedi market quote abcbourse FR0000120073 --date=ge:2026-01-01 --select=l20

===== market sync-group =====

Description :
  Remplace transactionnellement la composition d'un groupe nommé à
  partir d'un fichier simple contenant un ISIN ou un ticker en début
  de ligne. Un libellé peut suivre après un espace, ';' ou ':'. Les
  lignes vides et celles commençant par # sont ignorées. Les membres
  absents du fichier sont retirés du groupe.

Usage :
  jedi market sync-group <source> <groupe> <fichier_references> [options]

Arguments requis :
  <source>                         Source de la base
  <groupe>                         Code libre du groupe, par exemple PEA
  <fichier_references>             Fichier contenant un ISIN ou ticker en début de ligne

Options :
      --universe=NAME              Univers général utilisé dans le nom de la base (défaut : france)
      --as-of=DATE                 Date de référence de la composition du groupe, au format AAAA-MM-JJ
      --reference-source=NAME      Source de référence de la composition du groupe
  -h, --help                       Affiche cette page d'aide

Exemple :
  jedi market sync-group abcbourse PEA pea.txt --reference-source=prorealtime --as-of=2026-09-24

===== market update =====

Description :
  Fusionne sans suppression les titres et cotations dans un dataset
  existant. Les doublons équivalents sont ignorés ; une cotation
  conflictuelle est signalée et ignorée. Une extension située à plus de
  7 jours calendaires de la fin actuelle du dataset est refusée, sauf
  avec --allow-gap.

Usage :
  jedi market update <source> <dataset> <quotes> <labels> [options]

Arguments requis :
  <source>                         Source de la base
  <dataset>                        Code du dataset à mettre à jour
  <quotes>                         Fichier de cotations de mise à jour
  <labels>                         Fichier de libellés ISIN;Name;Ticker

Options :
      --universe=NAME              Univers général utilisé dans le nom de la base (défaut : france)
      --date-order=ORDER           Ordre de date : auto, ymd, dmy ou mdy (défaut : auto)
      --year-pivot=NN              Pivot des années sur deux chiffres, de 0 à 99 (défaut : 70)
      --from=DATE                  Première date de cotation conservée, au format AAAA-MM-JJ
      --allow-gap                  Accepte explicitement une lacune historique supérieure à 7 jours calendaires
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi market update abcbourse Euronext_A Euronext_A_update.txt labels.txt
  jedi market update abcbourse Euronext_A Euronext_A_update.txt labels.txt --allow-gap

===== note create =====

Description :
  Crée une nouvelle note

Usage :
  1ère forme, avec un éditeur externe :
    jedi note create --edit [options]

  2nde forme, avec champs nommés :
    jedi note create --date=DATE --summary=SUMMARY --contents=TEXT [options]
    
  3ème forme, avec champs positionnels :
    jedi note create <date> <summary> <contents> [options]

Notes :
  Il est recommandé d'utiliser l'option --edit pour permettre l'édition complète du texte 
  à l'aide de l'éditeur par défaut défini par les variables d'environnement EDITOR ou VISUAL.
  L'utilisation de champs nommés ou champs positionnels reste possible, mais peu commode. 
  ** Ne pas mélanger les syntaxes **

Champs requis :
      --date=DATE                  Date de création de la note
      --summary=SUMMARY            Résumé de la note
      --contents=TEXT              Contenu de la note

Options :
      --edit                       Crée la note à l'aide d'un éditeur externe
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi note create --edit
  jedi note create --date 2026-05-28 --summary "Renault\nsummary" --contents "Renault\ncontents"
  jedi note create 2026-05-28 "Renault\nsummary" "Renault\ncontents"

===== operation create =====

Description :
  Crée une nouvelle opération sur un trade existant

Usage: 
  1ère forme, avec champs nommés :
    jedi operation create <id | nom> --date=DATE --time=TIME --type=TYPE \
                                     --mode=MODE --quantity=QUANTITY \
                                     --price=PRICE [--fees=FEES] [options]

  2ème forme, avec champs positionnels :  
    jedi operation create <id | nom> <date> <time> <type> <mode> <quantity> \
                          <price> [fees] [options]

Notes :
  La syntaxe recommandée utilise un argument positionnel pour l'identifiant du trade
  et des champs nommés pour les autres paramètres.  
  La syntaxe positionnelle est un raccourci équivalent, sur champs requis uniquement.
  Un prix nul est réservé à une opération Sell qui solde intégralement le stock,
  par exemple après la liquidation du titre.
  ** Ne pas mélanger les syntaxes **

Arguments requis :
  <id>                             Id du trade dans la base de données             
  <nom>                            Nom du trade

Champs requis :
      --date=DATE                  Date de la transaction (format ISO 8601: YYYY-MM-DD)
      --time=TIME                  Heure de la transaction (format ISO 8601: HH:MM:SS)
      --type=TYPE                  Type de transaction : Buy ou Sell
      --mode=MODE                  Mode d'exécution : Market, Limit, Stop ou StopLoss
      --quantity=QTY               Quantité exécutée
      --price=PRICE                Prix d'exécution
                                   (utiliser la syntaxe +PRICE pour passer le contrôle du pas  
                                    de cotation)

Champs optionnels :
      --fees=FEES                  Frais de transaction 
                                   (à défaut, calculés selon les paramètres de configuration)

Options :
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi operation create g22 --date 2026-04-15 --time 15:00:00 --type Buy --mode Limit \
                            --quantity 100 --price 10.0
  jedi operation create 22 2026-04-15 15:00:00 Buy Limit 100 10.0

===== operation list =====

Description :
  Liste les opérations

Usage : 
  jedi operation list [filters] [options]

Filtres :
  -r, --running                    Trades en cours seulement

  [regex]                          Filtre regex, insensible à la casse, appliqué à 
                                   la concaténation des champs filtrables. 
                                   && = ET, || = OU, avec priorité de && sur ||.
                                   Exemples : abc, abc && xyz, abc || xyz, a && b || c && d.
                                   Chaque terme est une regex indépendante. L’ordre des champs
                                   n’a pas d’importance. Parenthèses non prises en charge.

                                   Les champs filtrables sont 'id', 'timestamp', 'type' et 
                                   'mode' de la table 'operation', ainsi que le champ 'name'
                                   des tables 'trade', 'security' et 'scale' (si l'option --csv est
                                   utilisée, l'option --extended doit également être
                                   utilisée pour étendre le filtrage à ces 3 derniers champs).

  -s, --select=RECORDS             Sélectionne uniquement les enregistrements définis 
                                   dans RECORDS, une liste d'éléments séparés par des 
                                   virgules, avec la syntaxe suivante :
                                   - la lettre F ou L (insensible à la casse), suivie 
                                     d'un entier, pour désigner respectivement les premiers 
                                     ou les derniers enregistrements à sélectionner
                                   - un nombre entier positif (ou négatif pour l'indexation 
                                     en fin de tableau)
                                   - une plage composée de deux entiers, positifs ou négatifs, 
                                     séparés par deux points
                                   Exemple : "f10,-12:-1" pour sélectionner les 10 premiers 
                                             enregistrements et les 12 derniers.
Notes:
  Le filtrage est réalisé dans l'ordre suivant :
    1. Trades en cours
    2. regex (Expression régulière)
    3. Sélection d'enregistrements

Options :
  -g, --group                      Groupe les opérations par nom de trade
  -c, --column-indexes=INDEXES     Sélectionne les index de colonne à afficher à l'aide d'une
                                   liste d'entiers ou d'une plage d'entiers, par exemple :
                                   1,2,5-8,10,13-16. Les colonnes seront affichées dans 
                                   l'ordre des index, et les plages peuvent être inversées 
                                   (ex. : l'ordre 2,1,8-5,15,10 donnera 2,1,8,7,6,5,15,10)
                                   (Non compatible avec l'option --csv)
      --csv                        Exporte les enregistrements au format CSV
      --headers                    Inclut les entêtes lorsque l'option --csv est activée
  -x, --extended                   Avec l'option CSV, ajoute les noms de trade, 
                                   de titre et de barème
  -h, --help                       Affiche cette page d'aide

Exemple:
  jedi operation list "Market && scale=qdt"

===== quote refresh =====

Description :
  Met à jour les cotations via les fournisseurs de données

Usage: 
  jedi quote refresh [filters] [options]

Filtres :
  [regex]                          Filtre regex, insensible à la casse, appliqué à 
                                   la concaténation des champs filtrables. 
                                   && = ET, || = OU, avec priorité de && sur ||.
                                   Exemples : abc, abc && xyz, abc || xyz, a && b || c && d.
                                   Chaque terme est une regex indépendante. L’ordre des champs
                                   n’a pas d’importance. Parenthèses non prises en charge.

                                   Les champs filtrables sont 'id', 'isin', 'name' et 'ticker'
Notes :
  Par défaut, seuls les titres liés aux trades en cours sont mis à jour

Options :
  -m, --mode=MODE                  Mode de cotation: 'live' ou 'eod' (défaut: 'live')
                                     - 'live' : mode pour l'extraction de données sur le Web 
                                     - 'eod' (End of Day) : mode pour le téléchargement direct
                                       (généralement non gratuit)
      --force                      Force la mise à jour de tous les titres, selon filtrage.
  -h, --help                       Affiche cette page d'aide

Exemples:
  jedi quote refresh "isin=FR000005.*"
  jedi quote refresh "MEDCL || ALCJ" --force

usage :

===== settings create =====

Description :
  crée un nouveau paramétrage de trade

Usage : 
  1ère forme, avec champs nommés :
    jedi settings create <Trade: id | name> --scale <id | name> --date=DATE --time=TIME \
                         [--split=NEW:OLD] [--sync=POSITION] [--reinit=VALUE] [options]

  2ème forme, avec champs positionnels :
    jedi settings create <Trade: id | name> <Scale: id | name> <date> <time> \
                         [--split=NEW:OLD] [--sync=POSITION] [--reinit=VALUE] [options]

Notes:
  La syntaxe recommandée utilise un argument positionnel pour l'identifiant du trade
  et des champs nommés pour les autres paramètres.  
  La syntaxe positionnelle est un raccourci équivalent, sur les champs requis uniquement
  ** Ne pas mélanger les syntaxes **

Arguments requis:
  <id>                             Id du trade dans la base de données             
  <name>                           Nom du trade

Champs requis :
      --scale=ID                   Identifiant de barème par son Id dans la table 'scale'
      --scale=NAME                 Identifiant de barème par son nom
      --date=DATE                  Date de prise d'effet (format ISO 8601: YYYY-MM-DD)
      --time=TIME                  Heure de prise d'effet (format ISO 8601: HH:MM:SS)

Options :
      --sync=POSITION              Après un 'gap' important ou un abandon temporaire du trade, resynchronise 
                                   la position au niveau d'un cours théorique :
                                   - immédiatement inférieur au prix courant en cas de hausse,
                                   - immédiatement supérieur au prix courant en cas de baisse.
                                   ** Cette option n'est applicable qu'aux barèmes de Type I **

      --split=NEW:OLD              Effectue un fractionnement ou un regroupement d'actions, selon le ratio
                                   défini par les valeurs 'NEW' et 'OLD', c'est-à-dire 'NEW' actions
                                   nouvelles pour 'OLD' actions anciennes.

      --reinit=VALUE               Réinitialise le trade avec VALUE = 'reset,<price>' ou 'merge,<price>' :
                                   - le résultat financier des transactions passées est conservé
                                   - l'historique des paramétrages précédents est oublié
                                   - Selon les paramètres passés à l'option, la base de calcul (q0 et c0) 
                                     est redéfinie comme suit:
                                     - Avec 'reset, <price>' : q0 prend la valeur du stock existant, 
                                       c0 prend la valeur du paramètre <price>
                                     - Avec merge, <price>, q0 et c0 résultent d'un calcul pondéré 
                                       prenant en compte leurs valeurs présentes et celles de la 
                                       transaction à suivre, achat ou vente, à l'initiative de l'utilisateur. 
                                       Cela permet d'augmenter ou de réduire le montant investi sur le trade.

  -h, --help                       Affiche cette page d'aide

Exemples:
  jedi settings create g22 --scale=qdt --date 2026-04-15 --time 15:00:00

===== tools profile =====

Profil Jedi détaillé ou synthétique
Usage :
  Profil détaillé depuis un fichier :
    jedi tools profile [options] <fichier_cotations>

  Profil détaillé depuis SQLite :
    jedi tools profile [options] --database=SOURCE --security=IDENT

      --security=IDENT --security=IDENT [...]

Argument positionnel :
  <fichier_cotations>               Fichier préparé contenant un seul titre
                                    (mode fichier uniquement)


Source et périmètre :
      --database=SOURCE            Charge les cotations depuis la base de marché SOURCE
      --universe=NAME              Sélectionne l'univers NAME (défaut : france)
      --security=IDENT             Sélectionne un titre par ISIN ou ticker ; option répétable
      --dataset=CODE               Sélectionne tous les titres du dataset CODE

Filtrage de la sélection :
      --group=CODE                 Ne conserve que les titres membres du groupe CODE
      --include-rejected           Inclut les candidats écartés

Sélection de l'historique :
      --date=OP:DATE               Sélectionne une période avec OP:AAAA-MM-JJ (ge, gt, le ou lt)
  -s, --select=RECORDS             Sélectionne uniquement les enregistrements définis 
                                   dans RECORDS, une liste d'éléments séparés par des 
                                   virgules, avec la syntaxe suivante :
                                   - la lettre F ou L (insensible à la casse), suivie 
                                     d'un entier, pour désigner respectivement les premiers 
                                     ou les derniers enregistrements à sélectionner
                                   - un nombre entier positif (ou négatif pour l'indexation 
                                     en fin de tableau)
                                   - une plage composée de deux entiers, positifs ou négatifs, 
                                     séparés par deux points
                                   Exemple : "f10,-12:-1" pour sélectionner les 10 premiers 
                                             enregistrements et les 12 derniers.

Présentation :
      --sort=KEY                   Trie selon KEY ; les valeurs de KEY sont toujours en anglais (voir Notes)
      --rank-criteria=N            Utilise les N premiers critères dans le total global (1 à 7 ; défaut 7)
      --limit=COUNT                Limite le résultat affiché aux COUNT premiers titres

Notes :
  Par défaut, une sélection en base est classée par rang global.
  Le rang global additionne, sans pondération, les rangs obtenus sur les N premiers critères dans cet ordre :
  tendance, liquidité, volatilité, oscillation, drawdown, gap et pas.
  N est choisi avec --rank-criteria=N (1 à 7, défaut 7).
  Les critères placés après N restent affichés à titre informatif mais n'influencent ni le total ni les égalités.
  Deux valeurs identiques pour un critère reçoivent le même rang.
  Le total le plus faible est classé en premier. En cas d'égalité, seuls les rangs retenus sont
  départagés dans cet ordre, puis par ticker.
  Les valeurs de --sort ne sont jamais traduites et doivent toujours être saisies en anglais :
  global, ticker, trend, liquidity, volatility, oscillation, drawdown, gap, step.
  Le rang global est relatif à la sélection courante : modifier la sélection peut modifier les rangs.
  Les titres écartés n'entrent jamais dans le classement global ; --include-rejected les affiche avec "-"
  pour Total/Rangs sans modifier les rangs des candidats retenus.
  Les critères tendance, liquidité, oscillation, drawdown, gaps et pas utilisent les 252 dernières séances ;
  l’ATR utilise les 20 dernières séances. La profondeur historique minimale reste un contrôle de qualité séparé.
  La fraîcheur est évaluée en séances de marché par rapport à la date de fraîcheur globale du dataset :
  la dernière date atteinte par au moins 95 % de ses titres, recalculée après chaque import ou mise à jour.
  Elle n'est pas évaluée avec un fichier, une sélection historique (--date/--select), un dataset sans
  fraîcheur validée, ou lorsqu'un titre appartient à plusieurs datasets sans qu'un --dataset explicite
  ne lève l'ambiguïté.

Colonnes du tableau :
  Total     Somme non pondérée des N premiers rangs choisis par --rank-criteria ; plus petit = mieux.
  Rangs     Sept rangs par importance ; "|" sépare les rangs retenus des rangs seulement informatifs.
  Ticker    Code du titre.
  Nom       Nom du titre.
  Ans       Profondeur de l'historique en années.
  Ret.      Retard en séances par rapport à la fraîcheur globale du dataset (95 %) ; '-' si indisponible.
  Tend%/a   Tendance annualisée sur 252 séances ; --sort=trend, plus élevée = mieux.
  Val.méd   Montant quotidien médian échangé sur 252 séances ; --sort=liquidity, plus élevé = mieux.
  ATR%      ATR(20) en pourcentage ; contribue à --sort=volatility.
  Range%    Amplitude sur 252 séances ; contribue à l'appréciation d'oscillation.
  Sw5/a     Oscillations d'au moins 5 % annualisées depuis les 252 dernières séances ; contribue à --sort=oscillation.
  DD%       Drawdown maximal sur 252 séances ; --sort=drawdown, plus faible = mieux.
  Gap%      Fréquence des gaps d'au moins 3 % sur 252 séances ; --sort=gap, plus faible = mieux.
  Pas%      Pas de barème suggéré ; --sort=step, plus faible = mieux.
  Mouv/a    Mouvements annuels estimés avec le pas suggéré ; information, pas un tri séparé.
  Statut    retenu, vigilance ou écarté.
  Aler.     Nombre de points de vigilance.

Valeurs de --sort :
  global      Total des N premiers rangs choisis par --rank-criteria, croissant.
  ticker      Ticker, ordre alphabétique neutre.
  trend       Tend%/a, décroissant.
  liquidity   Val.méd, décroissant.
  volatility  Classe de volatilité, puis ATR% croissant à classe égale.
  oscillation Classe d'oscillation (Sw5/a + Range%), puis Sw5/a décroissant à classe égale.
  drawdown    DD%, croissant.
  gap         Gap%, croissant.
  step        Pas%, croissant.

Seuils de vigilance utilisés par le Statut :
  Sw5/a < 4,0 par an, Gap% > 3,0 %, DD% > 45,0 %.
Classes utilisées pour le tri volatilité :
  bonne 2,0-5,0 % ; correcte 1,5-<2,0 % ou >5,0-6,0 % ; faible >6,0-8,0 % ; mauvaise >8,0 %.
  Un ATR(20) inférieur à 1,5 % est éliminé avant classement.
Classes utilisées pour le tri oscillation :
  excellente : Sw5/a >= 8 et Range% 40-100 ; bonne : Sw5/a >= 4 et Range% 40-100 ;
  correcte : Sw5/a >= 3 et Range% 30-120 ; faible : Sw5/a >= 1 ; mauvaise : Sw5/a < 1.


Options :
  -h, --help                       Affiche cette page d'aide

Exemples :
  jedi tools profile cotations_RNO.txt
  jedi tools profile --database=abcbourse --security=RNO
  jedi tools profile --database=abcbourse --dataset=Euronext_A --group=PEA
  jedi tools profile --database=abcbourse --group=PEA
  jedi tools profile --database=abcbourse --group=PEA --rank-criteria=4
  jedi tools profile --database=abcbourse --dataset=Euronext_A \
    --group=PEA --date=ge:2020-01-01 --sort=liquidity --limit=20
  jedi tools profile --database=abcbourse \
    --security=RNO --security=AI --security=BNP --include-rejected

                                   Chaque terme est une regex indépendante. L’ordre des champs
                                   n’a pas d’importance. Parenthèses non prises en charge.

                                   les champs filtrables sont 'name' de la table 'trade' et 
                                   'name' de la table 'security'

Options :
      --tick-buy=TICK_VALUE        Définit la valeur du pas de cotation à l'achat pour le titre 
                                   sous-jacent (uniquement si un seul trade a été sélectionné)
      --tick-sell=TICK_VALUE       Définit la valeur du pas de cotation à la vente pour le titre
                                   sous-jacent (uniquement si un seul trade a été sélectionné)
      --net-stop                   Le cas échéant, indique la quantité du stop-loss déduction 
                                   faite de l'ordre de vente à cours limité
      --update-now                 Force la mise à jour des cotations
  -h, --help                       Affiche cette page d'aide

Exemple:
  jedi trade orders g12

===== trade update =====

Description :
  Met à jour un ou plusieurs champs d'un trade

Usage :
  jedi trade update <id | name> [options]

Arguments requis:
  <id>                             Id du trade dans la base de données
  <name>                           Nom du trade

Champs optionnels :
      --name=NAME                  Nom du trade :
                                     - Doit commencer par une lettre
                                     - Suivie d'au moins une lettre, un chiffre ou un souligné.
      --money=MONEY                Nouvelle définition de la gestion du capital, acceptée 
                                   seulement si le champ 'stop' est 'null' ou si l'option 
                                   --reset-stop est activée.
                                   (Voir la commande 'trade create' pour la syntaxe à utiliser)

Options :
      --reset-stop                 Réinitialise le champ 'stop' à 'null', effaçant les données 
                                   d'un stoploss existant
  -h, --help                       Affiche cette page d'aide

Exemple:
  jedi trade update G01 --name "XG01"
