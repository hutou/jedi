===== main =====

jedi, version 1.0.0

The jedi application can be used in 'command line' mode only, using the
following syntax:

jedi [global options] command subcommand arguments [options]

Entering a command alone displays the list of sub-commands available
for this command.

- Arguments and options apply only to the sub-command that precedes them.
  At this level are defined:
  . whether or not arguments are mandatory
  . availability of options
- If no arguments are required, the subcommand is executed immediately.
- All subcommands have a help page that can be accessed using the -h or --help option.  

A double dash “--” must be used to separate options and positional
arguments (mandatory if these start with a single dash, as in the case
of negative numbers). So be careful when placing options in this case;
they must always precede the double dash.

When an option or positional argument expects a list, the elements of 
this list must be separated by a comma, with no intervening spaces 
(except if surrounded by double quotes).

Commands:
  security                         Manage listed securities (securities, ETFs, funds…)
  quote                            Manages quotes
  trade                            Manage trades (create, update, ...)
  scale                            Manage scales (Type I and type II)
  settings                         Manage settings (scale, split)
  operation                        Manage operations
  note                             Manage notes
  database                         Manage database
  market                           Manages market quotation databases
  tools                            Jedi toolbox

  version                          Display version details
  config                           Display configuration data
                                   (Use --paths option to only display files in use)"
                                   
Notes:
  Commands and subcommands can be abbreviated to the shortest unambiguous prefix.

Global options:
  -b, --border=PRESET              Select border style, among following values:
                                     - ascii         - modern         - markdown   - empty 
                                     - reducedascii  - reducedmodern  - fancy      - blank

===== market group =====

Description:
  Adds one security to an existing group or removes it.

Usage:
  jedi market group <source> <group> <ISIN> (--add | --remove) [options]

Required arguments:
  <source>                         Database source
  <group>                          Existing group code
  <ISIN>                           Security ISIN

Options:
      --universe=NAME              General universe used in the database name (default: france)
      --add                        Add the security to the group
      --remove                     Remove the security from the group
  -h, --help                       Show this help

Examples:
  jedi market group abcbourse PEA FR0000031122 --add
  jedi market group abcbourse PEA FR0000031122 --remove

===== market import =====

Description:
  Adds a set of securities and quotations to an existing database.
  ISINs without labels are skipped and listed in the report.

Usage:
  jedi market import <source> <dataset> <quotes> <labels> [options]

Required arguments:
  <source>                         Database source
  <dataset>                        Free dataset code, for example Euronext_A
  <quotes>                         Quotation file
  <labels>                         ISIN;Name;Ticker labels file

Options:
      --universe=NAME              General universe used in the database name (default: france)
      --date-order=ORDER           Date order: auto, ymd, dmy or mdy (default: auto)
      --year-pivot=NN              Two-digit year pivot from 0 to 99 (default: 70)
      --from=DATE                  First quotation date retained, in YYYY-MM-DD format
  -h, --help                       Show this help

Examples:
  jedi market import abcbourse Euronext_A Euronext_A.txt labels.txt
  jedi market import abcbourse Euronext_A Euronext_A.txt labels.txt --from=2020-01-01

===== market list =====

Description:
  Lists securities stored in the market database. --dataset can restrict
  the list to one dataset. An optional regex filter can target all fields
  or a named field.

Usage:
  jedi market list <source> [regex] [options]

Required arguments:
  <source>                         Database source

Filters:
  [regex]                          Regex filter, case insensitive, on the concatenation 
                                   of all filterable fields.
                                   && = AND, || = OR, with && before ||.
                                   Examples: abc, abc && xyz, abc || xyz, a && b || c && d.
                                   Each term is an independent regex. Field order does not 
                                   matter. No parentheses support.

                                   Filterable fields are: isin, ticker, name, group, dataset.
Options:
      --universe=NAME              General universe used in the database name (default: france)
      --dataset=CODE               Limits the report to the specified dataset
      --last-quote                 Add the date and closing price of the last quote
  -h, --help                       Show this help

Examples:
  jedi market list abcbourse
  jedi market list abcbourse air
  jedi market list abcbourse 'group=PEA && name=air'
  jedi market list abcbourse --dataset=Euronext_Growth
  jedi market list abcbourse 'ticker=^AL' --dataset=Euronext_A
  jedi market list abcbourse --last-quote

===== market quote =====

Description:
  Displays the complete OHLCV history of one market security. Date
  selection is applied before record selection.

Usage:
  jedi market quote <source> <ISIN> [options]

Required arguments:
  <source>   Database source
  <ISIN>     Security ISIN

Options:
      --universe=NAME              General universe used in the database name (default: france)
  -s, --select=RECORDS             Selects the records defined in RECORDS, a comma-separated 
                                   list of elements, with the following syntax:
                                   - The letter F or L (case insensitive), followed by an 
                                     integer, to designate the first or last records to be 
                                     selected, respectively
                                   - A positive or (negative integer for end-of-array indexing)
                                   - A range of two integers, positive or negative, separated 
                                     by a colon.
                                   Example: "f10,-12:-1" for selecting the first 10 records 
                                            and the last 12 ones
      --date=OP:DATE               Selects a period with OP:YYYY-MM-DD (ge, gt, le or lt)
  -h, --help                       Show this help

Examples:
  jedi market quote abcbourse FR0000120073
  jedi market quote abcbourse FR0000120073 --date=ge:2026-01-01
  jedi market quote abcbourse FR0000120073 --select=20
  jedi market quote abcbourse FR0000120073 --date=ge:2026-01-01 --select=l20

===== market sync-group =====

Description:
  Transactionally replaces the membership of a named group from a
  simple file containing an ISIN or ticker at the beginning of each
  line. A label may follow after whitespace, ';' or ':'. Blank lines
  and lines beginning with # are ignored. Existing members absent from
  the file are removed from the group.

Usage:
  jedi market sync-group <source> <group> <references_file> [options]

Required arguments:
  <source>                         Database source
  <group>                          Free group code, for example PEA
  <references_file>                File containing an ISIN or ticker at line start

Options:
      --universe=NAME              General universe used in the database name (default: france)
      --as-of=DATE                 Group membership reference date in YYYY-MM-DD format
      --reference-source=NAME      Reference source for group membership
  -h, --help                       Show this help

Example:
  jedi market sync-group abcbourse PEA pea.txt --reference-source=prorealtime --as-of=2026-09-24

===== market update =====

Description:
  Non-destructively merges securities and quotations into an existing
  dataset. Equivalent duplicates are ignored; a conflicting quotation
  is reported and skipped. An extension more than 7 calendar days
  after the current dataset end is rejected unless --allow-gap is used.

Usage:
  jedi market update <source> <dataset> <quotes> <labels> [options]

Required arguments:
  <source>                         Database source
  <dataset>                        Dataset code to update
  <quotes>                         Quotation update file
  <labels>                         ISIN;Name;Ticker labels file

Options:
      --universe=NAME              General universe used in the database name (default: france)
      --date-order=ORDER           Date order: auto, ymd, dmy or mdy (default: auto)
      --year-pivot=NN              Two-digit year pivot from 0 to 99 (default: 70)
      --from=DATE                  First quotation date retained, in YYYY-MM-DD format
      --allow-gap                  Explicitly accepts a history gap larger than 7 calendar days
  -h, --help                       Show this help

Examples:
  jedi market update abcbourse Euronext_A Euronext_A_update.txt labels.txt
  jedi market update abcbourse Euronext_A Euronext_A_update.txt labels.txt --allow-gap

===== operation create =====

Description:
  Create a new operation for an existing trade

Usage: 
  1st form, with named fields:
    jedi operation create <id | name> --date=DATE --time=TIME --type=TYPE \
                                     --mode=MODE --quantity=QUANTITY \
                                     --price=PRICE [--fees=FEES] [options]

  2nd form, with positional fields:
    jedi operation create <id | name> <date> <time> <type> <mode> <quantity> <price> \
                           [--fees=FEES] [options]

Notes:
  The recommended syntax uses one positional argument for the trade identifier
  and named options for the other parameters.
  The positional syntax is a shorthand equivalent, on required fields only.
  A zero price is reserved for a Sell operation that closes the entire stock,
  for example after the security has been liquidated.
  ** Do not mix syntaxes **

Required arguments:
  <id>                             Trade Id in the database     
  <name>                           Name of the trade

Required fields:
      --date=DATE                  Transaction date (format ISO 8601: YYYY-MM-DD)
      --time=TIME                  Transaction time (format ISO 8601: HH:MM:SS)
      --type=TYPE                  Transaction type : Buy or Sell
      --mode=MODE                  Execution mode : Market, Limit, Stop or StopLoss
      --quantity=QTY               Execution quantity
      --price=PRICE                Execution price
                                   (use +PRICE syntax to skip tick check)

Optional fields:
      --fees=FEES                  Transaction fees 
                                   (default: calculated based on configuration data)

Options:
  -h, --help                       Show this help

Examples:
  jedi operation create g22 --date 2026-04-15 --time 15:00:00 --type Buy --mode Limit \
                            --quantity 100 --price 10.0
  jedi operation create 22 2026-04-15 15:00:00 Buy Limit 100 10.0

===== scale create =====

Description:
  Create a new scale

Usage:
  1st form, with named fields:
    jedi scale create --name=NAME --comment=COMMENT --builder=BUILDER [options]
  2nd form, with positional fields:
    jedi scale create <name> <comment> <builder> [options]

Notes:
  The recommended syntax uses named options for all parameters.
  The positional syntax is a shorthand equivalent.
  ** Do not mix syntaxes **

Required fields:
      --name=NAME                  Scale Name:
                                     - Must begin with a letter,
                                     - Followed by at least one alphanumeric character.
      --comment=COMMENT            Comment on scale (free-form)
      --builder=BUILDER            Valid scale builder keyword sets:
                                     - {kc,ks,ki,kb}           : Type I, canonical format
                                     - {kc,ki,kb,kd}           : Type I, optimized on ks
                                     - {vr,ks,ki,kb}           : Type II, canonical format
                                     - {vr,np,nn,ki,kb,kd}     : Type II, optimized on ks
                                     - {vr,np,sr,nn,mi,ki,kb}  : Type II, legacy
                                   Each keyword expects one or more parameters:
                                     - np, nn, mi, kb: a single integer value (e.g., np:3)
                                     - kc, ks: a list of decimal values, separated by commas 
                                       (e.g., kc:1.45,1.30, 1.15, ...)
                                     - vr, sr, ki, kd: a single decimal value (which can be expressed 
                                       as a percentage, except for kd)
                                       (e.g., vr:15% or vr:0.15)

Options:
  -h, --help                       Show this help

Examples:
  jedi scale create --name sc01 --comment "scale 01" --definition "vr:15%, np:3, nn:3, ki:15%, kb:1, kd:0.3"
  jedi scale create sc01 "scale 01" "vr:15%, np:3, nn:3, ki:15%, kb:1, kd:0.3"

===== tools profile =====

Detailed or summary Jedi profile
Usage:
  Detailed profile from a file:
    jedi tools profile [options] <quotes_file>

  Detailed profile from SQLite:
    jedi tools profile [options] --database=SOURCE --security=IDENT

  Named group selection:

    jedi tools profile [options] --database=SOURCE \
      --security=IDENT --security=IDENT [...]

Positional argument:
  <quotes_file>                     Prepared file containing one security
                                    (file mode only)


Source and scope:
      --database=SOURCE            Load quotations from market database SOURCE
      --universe=NAME              Select market universe NAME (default: france)
      --security=IDENT             Select a security by ISIN or ticker; repeatable option
      --dataset=CODE               Select all securities in dataset CODE

Selection filters:
      --group=CODE                 Keep only securities belonging to group CODE
      --include-rejected           Include rejected candidates

History selection:
      --date=OP:DATE               Selects a period with OP:YYYY-MM-DD (ge, gt, le or lt)
  -s, --select=RECORDS             Selects the records defined in RECORDS, a comma-separated 
                                   list of elements, with the following syntax:
                                   - The letter F or L (case insensitive), followed by an 
                                     integer, to designate the first or last records to be 
                                     selected, respectively
                                   - A positive or (negative integer for end-of-array indexing)
                                   - A range of two integers, positive or negative, separated 
                                     by a colon.
                                   Example: "f10,-12:-1" for selecting the first 10 records 
                                            and the last 12 ones

Presentation:
      --sort=KEY                   Sort by KEY; KEY values are always the English identifiers listed in Notes
      --rank-criteria=N            Use the first N ranking criteria in the global total (1 to 7; default 7)
      --limit=COUNT                Limit the displayed result to the first COUNT securities

Notes:
  By default, a database selection is ordered by global rank.
  The global rank adds, without weighting, the ranks obtained from the first N criteria in this order:
  trend, liquidity, volatility, oscillation, drawdown, gap and step.
  N is selected with --rank-criteria=N (1 to 7, default 7).
  Criteria after N stay visible for information but do not affect the total or tie-breaking.
  Equal values for one criterion receive the same rank.
  The lowest total ranks first. Ties are broken by the included ranks in that order, then by ticker.
  --sort values are never translated and must always use these English identifiers:
  global, ticker, trend, liquidity, volatility, oscillation, drawdown, gap, step.
  The global rank is relative to the current selection: changing the selection can change ranks.
  Rejected securities never enter the global ranking; --include-rejected displays them with "-" for Total/Ranks
  and does not change the ranks of retained candidates.
  Trend, liquidity, oscillation, drawdown, gaps and step use the latest 252 sessions;
  ATR uses the latest 20 sessions. Minimum history depth remains a separate quality check.
  Freshness is assessed in market sessions against the dataset's global freshness date:
  the latest date reached by at least 95% of its securities, recomputed after each import or update.
  It is not assessed for files, filtered historical selections (--date/--select),
  datasets without a validated freshness date, or securities belonging to several datasets
  when no explicit --dataset resolves that ambiguity.

Table columns:
  Total     Unweighted sum of the first N ranks selected by --rank-criteria; lower is better.
  Ranks     Seven ranks in importance order; "|" separates included from informative-only ranks.
  Ticker    Security ticker.
  Name      Security name.
  Years     History depth in years.
  Lag       Sessions behind the dataset's global freshness date (95%); '-' when unavailable.
  Trend%/y  Annualized trend over 252 sessions; --sort=trend, higher is better.
  Med.val   Median daily traded value over 252 sessions; --sort=liquidity, higher is better.
  ATR%      ATR(20) as a percentage; contributes to --sort=volatility.
  Range%    252-session range; contributes to the oscillation assessment.
  Sw5/y     Swings of at least 5%, annualized from the latest 252 sessions; contributes to --sort=oscillation.
  DD%       Maximum drawdown over 252 sessions; --sort=drawdown, lower is better.
  Gap%      Frequency of gaps of at least 3% over 252 sessions; --sort=gap, lower is better.
  Step%     Suggested Jedi scale step; --sort=step, lower is better.
  Mov/y     Estimated annual moves at the suggested step; information, not a separate sort.
  Status    retained, warning or rejected.
  Warn.     Number of warnings.

--sort values:
  global      Total of the first N ranks selected by --rank-criteria, ascending.
  ticker      Ticker, neutral alphabetical order.
  trend       Trend%/y, descending.
  liquidity   Med.val, descending.
  volatility  Volatility class, then ATR% ascending within the same class.
  oscillation Oscillation class (Sw5/y + Range%), then Sw5/y descending within the same class.
  drawdown    DD%, ascending.
  gap         Gap%, ascending.
  step        Step%, ascending.

Warning thresholds used by Status:
  Sw5/y < 4.0 per year, Gap% > 3.0%, DD% > 45.0%.
Volatility ranking classes:
  good 2.0-5.0%; acceptable 1.5-<2.0% or >5.0-6.0%; weak >6.0-8.0%; poor >8.0%.
  ATR(20) below 1.5% is rejected before ranking.
Oscillation ranking classes:
  excellent: Sw5/y >= 8 with Range% 40-100; good: Sw5/y >= 4 with Range% 40-100;
  acceptable: Sw5/y >= 3 with Range% 30-120; weak: Sw5/y >= 1; poor: Sw5/y < 1.


Options:
  -h, --help                       Show this help

Examples:
  jedi tools profile quotes_RNO.txt
  jedi tools profile --database=abcbourse --security=RNO
  jedi tools profile --database=abcbourse --dataset=Euronext_A --group=PEA
  jedi tools profile --database=abcbourse --group=PEA
  jedi tools profile --database=abcbourse --group=PEA --rank-criteria=4
  jedi tools profile --database=abcbourse --dataset=Euronext_A \
    --group=PEA --date=ge:2020-01-01 --sort=liquidity --limit=20
  jedi tools profile --database=abcbourse \
    --security=RNO --security=AI --security=BNP --include-rejected

===== trade create =====

Description:
  Create a new trade

Usage:
  1st form, with named fields:
    jedi trade create --name NAME --security <ID | ISIN> [--money MONEY] [options]

  2nd form, with positional fields
    jedi trade create <name> <Security: id | isin> [--money=MONEY] [options]

Notes:
  The recommended syntax uses named options for all parameters.
  The positional syntax is a shorthand equivalent, on required fields only.
  Do not mix both syntaxes.

Required fields:
      --name=NAME                  Trade Name:
                                     - Must begin with a letter
                                     - Followed by at least one letter, digit or underscore.
      --security=ID                Security id in the database
      --security=ISIN              Security ISIN code

Optional fields:
      --money=MONEY                Money definition:
                                     A comma-separated list of three parameters. 
                                     Each parameter is defined as <k>:<v>, where
                                     <k> is one of 'r', 'o' or 'n', and <v> is 
                                     its associated value:
                                       r:<v>  Maximum risk rate applied to the capital (K) 
                                              allocated to trading
                                       o:<v>  Financial objective coefficient 
                                              (applied to R = r × K)
                                       n:<v>  Jedi operating margin (number of down steps)
                                   
Options:
  -h, --help                       Show this help

Examples:
  jedi trade create --name G13 --security FR0000066722
  jedi trade create g13 FR0000066722 --money r:1.5%,o:1,n:2

Description:

Usage:
  jedi trade list [filters] [options]

Filters:
  -r, --running                    Running trades only

  [regex]                          Regex filter, case insensitive, on the concatenation 
                                   of all filterable fields.
                                   && = AND, || = OR, with && before ||.
                                   Examples: abc, abc && xyz, abc || xyz, a && b || c && d.
                                   Each term is an independent regex. Field order does not 
                                   matter. No parentheses support.

                                   The filterable fields are 'id', 'name', 'money' and 'stop'
                                   in the 'trade' table, as well as 'isin' and 'name' fields 
                                   in the 'security' table if the --extended option is enabled.

  -s, --select=RECORDS             Selects the records defined in RECORDS, a comma-separated 
                                   list of elements, with the following syntax:
                                   - The letter F or L (case insensitive), followed by an 
                                     integer, to designate the first or last records to be 
                                     selected, respectively
                                   - A positive or (negative integer for end-of-array indexing)
                                   - A range of two integers, positive or negative, separated 
                                     by a colon.
                                   Example: "f10,-12:-1" for selecting the first 10 records 
                                            and the last 12 ones
Notes:
  Filtering is done in the following order:
    1. Trades in progress
    2. Regular expression
    3. Record selection

Options:
      --csv                        Exports records in CSV format
      --headers                    Includes headers when CSV selected
  -x, --extended                   Includes security fields 'id', 'isin' and 'name'
  -c, --column-indexes=INDEXES     Select column indexes to display, using a list of integers
                                   or range of integers, such as 1,2,5-8,10,13-16. Columnswill
                                   be displayed in the order of indexes, and ranges can be 
                                   inverted (ex: 2,1,8-5,15,10 order will be 2,1,8,7,6,5,15,10)
                                   (not compatible with option --csv)
  -h, --help                       Show this help

Example:
